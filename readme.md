## 1) ¿Puedes identificar pruebas de unidad y de integración en la práctica que se realizó?

    Si se pueden identificar pruebas de unidad ya que se realizan las pruebas de los metodos de la tienda como agregar un producto, eliminar un producto y buscar un producto. Pero no se realizaron pruebas de integracion ya que no se realizaron las pruebas de todos estos metodos en conjunto.


## 2) ¿Podría haber escrito las pruebas primero antes de modificar el código de la aplicación?¿Cómo sería el proceso de escribir primero los tests?

    Si se podrían haber escrito las pruebas antes de modificar el codigo de la modificacion.

    Primero se escriben las pruebas que describen el comportamiento esperado del código antes de implementarlo. Luego, el desarrollo del código se enfoca en hacer que las pruebas pasen.


## 3) En lo que va del trabajo práctico, ¿puedes identificar 'Controladores' y 'Resguardos'? ¿Qué es un “test double”? ¿Hay otros nombres para los objetos/funciones simulados?

    Controladores son las pruebas que controlan el flujo de ejecución al llamar a los métodos de la clase que se están probando como pueden ser los metodos de aplicar descuento o buscar producto.

    Un test double es un objeto o componente que reemplaza a uno real durante una prueba, permitiendo aislar la unidad que se está probando y evitar dependencias innecesarias.
    Sí. Existen distintos tipos de test doubles, como mocks, stubs, dummies, fakes y spies.
